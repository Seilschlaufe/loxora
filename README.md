# Lexora

Русскоязычная PWA для чтения немецких, английских и испанских текстов. Нажатие на слово или выделенное выражение открывает разбор в контексте; карточку можно сохранить в личный словарь.

Приложение запускается без внешних сервисов в **явно обозначенном демонстрационном режиме**. Настоящий анализ требует OpenAI и входа через настроенный Supabase. Синхронизация хранит данные в PostgreSQL вашего проекта Supabase.

## Быстрый запуск без ключей

Понадобится Node.js 24 LTS (поддерживается Node.js от 22), npm и современный браузер.

```sh
cd /workspace/loxora  # или каталог, куда вы клонировали проект
npm ci
npm run dev
```

Откройте приложение на порту 3000. В обычной локальной разработке адрес — `http://localhost:3000`. Начните с демонстрационного текста или нажмите **«Добавить текст»**, укажите название и язык, вставьте обычный текст и сохраните его. Откройте читалку, нажмите на слово, затем **«Добавить в словарь»**.

В деморежиме данные остаются в IndexedDB этого браузера. Карточки помечены как тестовые; несколько языковых примеров заранее подготовлены, а неизвестные слова получают заглушку. **Это не настоящий контекстный анализ и не подтверждение качества ИИ.** Демо не вызывает OpenAI и не отправляет документы в облако. При входе создаётся отдельное пространство аккаунта; локальные демонстрационные тексты автоматически в него не импортируются.

## Что реализовано

- Библиотека: добавление, автоматический локальный черновик, название, язык, дата, поиск, переименование и удаление текстов.
- Читалка: точное сохранение пробелов и абзацев, интерактивные слова со смещениями UTF-16 через `Intl.Segmenter`, обычное выделение и копирование, анализ выражений до 200 символов, сохранение прокрутки.
- Карточка: краткий и подробный режимы, лемма, контекстный перевод, морфология, грамматика, перевод предложения, пример, альтернативные значения и замечания о неоднозначности. Переключение режима не вызывает модель повторно.
- Словарь: сохранение полной карточки и источника, поиск, фильтр языка, сортировка по дате, удаление и экспорт JSON/CSV. Разные контексты сохраняются отдельно; повторное сохранение защищено уникальным ключом.
- Серверный `/api/analyze`: проверка входа и доступности документа, проверка выделения по сохранённому тексту, ограниченный контекст, OpenAI Responses API и Structured Outputs с Zod.
- Кэш: локальный и серверный, с языком, выделением, контекстом и версией промпта в ключе; защита от одновременных повторов и показа устаревшего ответа.
- Email-вход Supabase Auth, PostgreSQL, миграция, RLS и изоляция пользователей, настройки и прогресс чтения в облаке.
- Светлая, тёмная и системная темы, размер шрифта, адаптивная карточка рядом со словом на ПК и нижняя панель на узком экране.
- PWA manifest, иконки, service worker, установка там, где её поддерживает браузер; офлайн-чтение загруженных текстов и открытие кэшированных карточек.
- Удаление собственных данных с сохранением самого аккаунта Auth.

## Подключение OpenAI

1. Скопируйте пример конфигурации:

   ```sh
   cp .env.example .env.local
   ```

2. Откройте `.env.local` в редакторе и заполните:

   ```dotenv
   OPENAI_API_KEY=ваш_серверный_ключ
   OPENAI_MODEL=gpt-4.1-mini
   NEXT_PUBLIC_SUPABASE_URL=https://ваш-проект.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=публичный_ключ_проекта
   ```

3. Укажите в `OPENAI_MODEL` доступную вашему проекту модель с поддержкой Responses API и Structured Outputs. Значение выше — используемое по умолчанию; доступность модели зависит от аккаунта.
4. Настройте Supabase по инструкции ниже, перезапустите Next.js и войдите через **«Настройки»**. При нажатии на новое слово сервер сделает настоящий запрос.

`OPENAI_API_KEY` читается только серверным обработчиком; у него нет префикса `NEXT_PUBLIC_`. Не добавляйте его в клиентский код, Git, скриншоты или сообщения. `.env.local` игнорируется Git. При размещении приложения заполните переменные через защищённые настройки хостинга. Переменные `NEXT_PUBLIC_*` являются публичными и встраиваются в клиентскую сборку: после их изменения нужна новая сборка.

OpenAI получает выбранный фрагмент и релевантный контекст, обычно предложение, а не весь документ. Для очень длинных предложений контекст обрезается вокруг выделения примерно до 1800 символов. Лимит ответа — 3500 токенов. Сервер проверяет схему, точное исходное выделение, язык и контекст до передачи карточки браузеру. Текст для модели считается недоверенным материалом, а не инструкциями.

Новый анализ требует подключения. Повторное открытие готовой карточки использует кэш. На пользователя действует лимит 20 новых запросов за скользящие 60 секунд. Неудачные попытки тоже учитываются; SDK может один раз повторить временно неудачный сетевой запрос. Есть тайм-аут 25 секунд на попытку. На хостинге разрешите серверной функции достаточную длительность с учётом повторной попытки (60 секунд, как указано в route.ts). Ошибки ключа, модели или квоты отображаются как ошибка, без подмены настоящего результата демоданными.

## Подключение Supabase

1. Создайте проект на Supabase и дождитесь готовности базы.
2. Откройте **SQL Editor** и выполните весь файл [supabase/migrations/202611080001_lexora.sql](supabase/migrations/202611080001_lexora.sql) один раз. Для нового проекта с CLI также можно использовать `supabase link --project-ref ...` и `supabase db push`.
3. В **Authentication → Providers → Email** включите Email-вход. Для полноценной эксплуатации настройте отправку писем/SMTP и лимиты согласно требованиям своего проекта.
4. В **Authentication → URL Configuration** задайте Site URL приложения. В Redirect URLs разрешите фактический адрес страницы `/settings`: например, `http://localhost:3000/settings` для локальной разработки и ваш HTTPS-адрес `/settings` для размещённого приложения.
5. Из настроек API проекта скопируйте URL и публичный `anon`/publishable key в `.env.local`, как показано выше. **Не используйте `service_role` или другой административный ключ**: он обходит RLS и не должен попадать в браузер.
6. Перезапустите приложение. В **«Настройки → Ваш аккаунт»** укажите email, получите письмо и откройте ссылку на устройстве, где хотите войти.

После входа изменения записываются в облако. Другой браузер с тем же аккаунтом получает библиотеку, словарь, настройки и прогресс при загрузке. Для обновления уже открытого приложения нажмите **↻** в верхней панели или перезагрузите страницу; восстановление подключения также запускает загрузку. Мгновенной подписки Realtime нет. Конкурирующие изменения разрешаются последней записью; совместное редактирование документов не предусмотрено.

Офлайн доступна локальная копия ранее загруженных данных. Изменения облачных документов, словаря и настроек без сети запрещены, очередь отложенной синхронизации не реализована. Деморежим может сохранять свои локальные данные. Выход очищает локальное пространство аккаунта на этом устройстве; очистка данных браузера также удаляет локальную копию. Чужой аккаунт получает отдельное пространство.

Таблицы: `documents`, `vocabulary_entries`, `reading_progress`, `analysis_cache`, `user_preferences`, `analysis_leases`. Везде включена RLS; составные внешние ключи запрещают ссылки на чужой документ. Широкие стандартные привилегии Supabase сужены до необходимых операций; `TRUNCATE`, обходящий RLS, не разрешён. Подробности схемы и RPC — в [supabase/README.md](supabase/README.md).

**«Удалить все мои данные»** удаляет тексты, слова, кэш, настройки и локальные копии текущего пространства. Слова сохраняются при удалении только их исходного документа, но ссылка на источник исчезает. Удаление всех данных не удаляет учётную запись Supabase Auth. Технические отметки квоты (UUID пользователя и время запросов, без текста и результатов) сохраняют ограничение на оставшуюся часть 60-секундного окна, чтобы удалением нельзя было сбросить лимит; устаревшие отметки физически очищаются при следующем запросе анализа или удалении данных. Административного удаления аккаунта из приложения нет.

## Production и установка PWA

```sh
npm ci
npm run typecheck
npm test
npm run build
npm start
```

Разместите приложение на хостинге с поддержкой Next.js App Router и Node.js server routes, задайте переменные окружения и HTTPS. Экспорт в полностью статические файлы не подходит для настоящего анализа. HTTPS нужен для service worker, безопасного локального хранения и стандартной установки PWA; `localhost` — исключение для разработки. Обычный HTTP по IP компьютера в локальной сети на телефоне этим исключением не является.

Откройте приложение онлайн хотя бы один раз и дайте загрузиться оболочке и текстам. На Android в Chrome откройте меню → **«Установить приложение»** / **«Добавить на главный экран»**, либо используйте кнопку установки в настройках Lexora, если браузер её предложил. На компьютере в Chrome/Edge нажмите значок установки в адресной строке или соответствующий пункт меню. На браузерах без установки приложение остаётся обычным адаптивным сайтом.

Service worker кэширует общую оболочку и статические ресурсы. API-ответы, внешние запросы и авторизационные URL не кэшируются. Личные тексты и карточки хранятся отдельно в IndexedDB. Новый анализ без сети не выполняется. Для проверки офлайн-режима и установки используйте production-сборку: dev-сервер меняет файлы и не является стабильной PWA-сборкой. После обновления версии может понадобиться закрыть и вновь открыть установленные окна; при изменении стратегии кэширования обновляйте версию кэша в `public/sw.js`.

## Проверки

```sh
npm run typecheck       # TypeScript
npm test                # модули, схема, обработчик API с изолированными зависимостями, PWA-контракт
npm run build           # production-сборка
npm run test:e2e         # браузерные сценарии, ПК и эмуляция Pixel 7
npm run test:db          # реальные SQL/RLS и конкурентные проверки в PostgreSQL через Docker
PLAYWRIGHT_PRODUCTION=1 npm run test:e2e  # после build: включая офлайн-перезагрузку PWA
```

Для E2E нужен Chromium: установите его командой `npx playwright install chromium`, а при необходимости системных библиотек следуйте подсказкам Playwright для вашей ОС. Конфигурация использует `/usr/bin/chromium`, если он уже есть, либо браузер Playwright. Свой исполняемый файл можно указать через `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Тестовый конфиг сам поднимает dev-сервер на порту 3000, если он ещё не запущен. Запускайте E2E с пустой конфигурацией Supabase для предсказуемого деморежима. Запущенный на том же порту production-сервер тоже можно использовать для отдельной проверки готовой сборки.

Модульные тесты проверяют сегментацию без потерь, границы контекста, разные значения в разных контекстах, проверку структуры, авторизацию, соответствие выделения документу, ошибки, кэш и параметры настоящего серверного запроса через mock SDK. E2E проверяют добавление/чтение/словарь, касание и клавиатуру, многословное выделение, кэш офлайн, маршруты и адаптивную ширину. Эмуляция Android не заменяет проверку на физическом телефоне.

`test:db` запускает закреплённый PostgreSQL 17 в временном Docker-контейнере без сети и открытых портов, применяет настоящую миграцию и выполняет проверки под двумя пользовательскими ролями. Проверяются RLS, запрет подмены владельца и `TRUNCATE`, внешние ключи, удаление, дедупликация, квоты и блокировки. Отдельно запускаются 24 одновременных запроса квоты и 8 запросов одного ключа. Контейнер удаляется после теста. Минимальный тестовый контракт Auth не является внешним Supabase Auth.

### Необязательные платные проверки качества модели

Обычный `npm test` **пропускает** live-тесты. Для осознанного запуска заполните `.env.local`, затем:

```sh
LEXORA_LIVE_AI_TESTS=1 node --env-file=.env.local node_modules/vitest/vitest.mjs run tests/live-ai.test.ts
```

Vitest сам не загружает `.env.local`, поэтому используется `node --env-file`. Эта команда обращается к OpenAI и расходует API-квоту. Проверяются `beschloss`, отделяемое `steht … auf`, `gave up`, `habíamos hablado` и разные значения `bank`. Проверки оценивают схему и грамматический/смысловой результат, а не единственную точную формулировку. Они не проверяют email-вход и внешний Supabase.

Без реальных ключей не считаются проверенными: доставка email, настоящий анализ OpenAI, работа внешнего проекта Supabase и синхронизация двух физических устройств. Их следует проверить после подключения: войти одним аккаунтом в двух браузерах, добавить текст/слово, обновить данные на втором устройстве, убедиться в изоляции другого аккаунта и выполнить запрос нового слова. Зелёные локальные тесты этого не подменяют.

```text
app/
  page.tsx, layout.tsx          общая оболочка, метаданные
  library/page.tsx             библиотека
  read/page.tsx                читалка
  vocabulary/page.tsx          словарь
  settings/page.tsx            аккаунт и настройки
  ui.tsx                      адаптивный интерфейс и прикладные действия
  style.css                   дизайн, темы и адаптивность
  api/analyze/route.ts         защищённый серверный анализ
lib/
  analysis.ts                 типы, Zod, сегментация, контекст, промпт и демо
  local.ts                    IndexedDB, пространства аккаунтов
  supabase.ts                 клиент БД и серверная проверка пользователя
public/
  manifest.webmanifest        установка PWA
  sw.js                       кэш общей оболочки
  icon*.png, icon.svg         обычные и maskable-иконки
supabase/
  migrations/                 схема, RLS, индексы и RPC
  tests/, test.sh             реальные SQL- и конкурентные проверки
  README.md                   контракт базы
tests/
  *.test.ts                   Vitest; live AI только по явному флагу
  e2e/                        Playwright: desktop и Android
.env.example                  только имена переменных, без секретов
package-lock.json             зафиксированное дерево зависимостей для npm ci
```

Используются Next.js App Router, React, TypeScript, OpenAI SDK, Zod, Supabase и IndexedDB (`idb`). Вместо Tailwind выбран обычный CSS: компактный проект имеет собственную небольшую дизайн-систему, которой достаточно для тем и адаптивности без дополнительной системы классов и конфигурации. Элементы управления используют стандартный HTML и видимый фокус; сторонняя библиотека UI не требуется для текущего объёма.

Тексты не вставляются через небезопасный HTML. Ввод ограничен в интерфейсе и в PostgreSQL (100 000 символов текста), а API анализа ограничивает тело запроса и проверяет смещения. Секреты OpenAI остаются на сервере; операции Supabase выполняются с JWT текущего пользователя и публичным ключом, без service_role. При настройке ограниченного сетевого доступа нужны HTTPS-домены `api.openai.com` и конкретного проекта `*.supabase.co` (разрешайте фактический hostname проекта), а для установки зависимостей — npm registry.

## Ограничения и дальнейшая работа

- Импортируется только обычный текст; PDF, EPUB и DOCX не поддерживаются.
- Качество грамматического и контекстного разбора зависит от выбранной модели. Промпт требует отмечать неоднозначность, но автоматическая проверка схемы не гарантирует лингвистическую истинность каждого ответа.
- Нет Realtime-подписок, фоновой очереди офлайн-изменений, разрешения конфликтов или импорта демоданных в аккаунт.
- Прогресс хранится как пиксельная позиция прокрутки; после изменения ширины экрана или размера шрифта место может немного сместиться.
- Локальные копии зависят от свободного места, настроек и очистки браузера. Перед важной очисткой экспортируйте словарь; экспорта всей библиотеки пока нет.
- Нет интерфейса удаления аккаунта Auth, восстановления удалённых записей, платёжных планов и мониторинга расходов по проекту. Для публичного сервиса дополнительно настройте эксплуатационные лимиты OpenAI/Supabase, резервное копирование и наблюдаемость.
- Автоматизированные тесты не подтверждают установку на конкретном физическом Android-устройстве и не заменяют проверку email/облачной синхронизации с вашими ключами.
- Интервальное повторение пока не реализовано. Его можно добавить отдельной таблицей `review_state` с владельцем, ссылкой на `vocabulary_entries`, датой следующего повторения и параметрами алгоритма; сохранённая структурированная карточка уже содержит материал для будущих упражнений.
